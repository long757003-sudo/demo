# 项目验收模块

[[全生命周期管理系统]] 第五步。权威版本：[[业务流程说明书V1.1]]（BPD-2026-005）。

## 模块概述

建设完成后进入验收阶段。承建方提交验收材料，系统执行前置校验（等保 / 软件测评 / 试运行时长）；项目负责人组织内部初验与强制试运行；信办管理员组织专家团队进行验收评审。通过后文档归档与资产移交，触发 [[项目运维模块]]。

## 主流程（9 步）

1. 承建方提交验收材料（需求规格说明书、测试报告、用户手册、安全检测报告、源代码/部署文档）
2. **子流程 K**：系统前置校验 → 状态「前置校验中」（任一项不通过 → 禁止提交）
3. 项目负责人组织二级单位内部初验 → 状态「内部初验中」（不合格 → **子流程 L**）
4. 系统启动试运行倒计时 → 状态「试运行中」（强制 ≥ 1 个月）
5. 试运行期满后提交正式验收申请 → 状态「正式验收申请」
6. 信办管理员组织验收评审 → 确定专家团队（**子流程 M**）→ 状态「验收评审中」
7. 专家执行 9 维度验收评审
8. 形成验收结论（不合格 → **子流程 N**）
9. 合格 → 文档归档、资产移交、使用推广 → 状态「验收通过·项目移交」 → 触发 [[项目运维模块]]

## 子流程

### K：前置校验（系统强制）

| 校验项 | 适用 | 不满足后果 |
| --- | --- | --- |
| 等保测评报告（第三方） | 所有项目 | 禁止提交 |
| 软件测评报告（第三方） | 软件开发类项目 | 禁止提交 |
| 试运行时长 ≥ 1 个月 | 所有项目 | 禁止提交 |

### L：内部初验整改

- 出具不合格清单 → 承建方限期整改 → 提交整改确认 → 重新初验
- 循环直至合格，合格后进入试运行

### M：验收专家团队要求

| 级别 | 专家要求 |
| --- | --- |
| 重大（≥ 500 万） | 校外专家须超过总人数一半 |
| 重大（< 500 万） | 校外专家不少于 2 人 |
| 中型 / 小型 / 微型 | 按 [[立项论证模块]] 专家规格执行 |

### N：验收不合格处理

- 第 1 次不合格 → 限期整改 → 重新提交验收申请
- 第 2 次不合格 → 系统锁定**半年**，期间不可再次提交（自动解锁），详见 [[项目锁定与解锁规则]]

## 验收评估 9 维度（第三十八条）

1. 建设目标达成度
2. 技术指标
3. 运行效果
4. 用户体验
5. 数据对接共享
6. 使用培训
7. 维保任务
8. 网络安全
9. 经费使用

## 核心状态

```
前置校验中 → 内部初验中 → 试运行中 → 正式验收申请
  → 验收评审中 → 验收通过·项目移交
```

## 业务规则（BR-26 ~ BR-30）

| 编号 | 规则 | 来源 |
| --- | --- | --- |
| BR-26 | 前置校验为系统强制，不可跳过 | 第三十八条 |
| BR-27 | 试运行最短 1 个月，系统强制控制 | 第三十八条 |
| BR-28 | 验收评审采用 9 维度评审 | 260409 会议 |
| BR-29 | 二次验收不合格锁定半年 | 第三十九条 |
| BR-30 | 重大项目（≥ 500 万）校外专家须过半 | 260409 会议 |

## 验收材料清单

需求规格说明书、设计文档、测试报告（含性能/压力测试）、用户手册、功能清单（合同 vs 实际对照表）、培训记录、安全检测报告、漏洞扫描报告、源代码/部署文档。

## 主要数据表

- `acceptance_material`：验收材料
- `internal_acceptance`：内部初验
- `trial_run`：试运行记录（含 `min_end_date = start_date + 30天` 约束）
- `formal_acceptance`：正式验收（含 `attempt_number`，二次不通过自动 + 半年）
- `project_handover`：项目移交
