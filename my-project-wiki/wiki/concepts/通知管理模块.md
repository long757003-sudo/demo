# 通知管理模块

系统全局消息与通知的配置、发送、查阅入口。与 [[通知矩阵]] 对应，覆盖全生命周期 6 大阶段的所有待办/待阅通知。

## 渠道策略（260409 会议确认）

| 渠道 | 状态 |
|------|------|
| 站内通知 | ✓ 启用 |
| 钉钉 | ✓ 启用 |
| 短信 | ✓ 启用（260409 新增） |
| 邮件 | ✗ 屏蔽（260409 决议） |

所有待阅、待办通知统一展示至通知列表。

## 子功能

### 1. 新建/编辑通知

内置 16 种通知类型，创建时可选择类型模板辅助填写。

### 2. 通知模板库（已上线 Demo，2026-04-10 归档）

**功能说明**

在「通知管理」分组下新增「通知模板」子菜单，提供全生命周期标准通知模板的只读浏览与快速跳转入口。

**权限**：仅 `info-admin`（信息办管理员）、`info-leader`（信息办领导）可见。

**视图 ID**：`notification-template`

**页面结构**

- 顶部：面包屑 `通知管理 > 通知模板库`
- 过滤栏：
  - 阶段下拉：全部 / 需求征集 / 立项论证 / 招采管理 / 项目实施 / 项目终止 / 项目验收 / 运维管理
  - 类型下拉：全部 / 待办 / 待阅
  - 模板总数统计 + 「重置」按钮
- 内容区：按模块分组（每个模块一张卡片 + `table-wrap` 标准表格），列结构：`#` \| 节点（节点编号 + 节点名称）\| 类型标签 \| 渠道徽章 \| 通知标题（含变量占位符）\| 正文摘要 \| 「使用」/「编辑」按钮
  > ⚠️ 历史版本曾有"接收角色"列，2026-04-14 调整为"节点"列，取消角色展示（通知触发由业务节点决定，接收角色不在模板库层面维护）

**模板数据覆盖（37 条静态 mock）**

| 模块 | 覆盖节点 | 条目数 |
|------|---------|-------|
| 需求征集 | 1-1 到 1-5 | 6 |
| 立项论证 | 2-1 到 2-7 | 8 |
| 招采管理 | 3-1 到 3-3 | 5 |
| 项目实施 | 4-1 到 4-4 | 6 |
| 项目终止 | 4-5 | 2 |
| 项目验收 | 5-2 到 5-6 | 6 |
| 运维管理 | 6-1 到 6-4 | 4 |
| **合计** | | **37** |

**「使用」按钮联动逻辑**

```
window._useTmpl(typeKey)
  ├── typeKey 在 _typeMap 中存在 → navigate('notification-create', {typeKey})
  │       notification-create 初始化时自动调用 _selectNotifType(typeKey) 预选类型
  └── 否则 → navigate('notification-create')
```

**实现说明**

- 数据为静态数组 `_tmplData`，内联在视图函数内（Demo 阶段不持久化）
- 涉及文件：`shared/nav.js`（菜单注册）、`shared/views/notification.js`（视图追加）
- 决策背景见：[[通知模板库功能决策]]
