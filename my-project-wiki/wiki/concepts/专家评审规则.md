# 专家评审规则

专家评审在 V1.1（[[业务流程说明书V1.1]]）中定位为**独立支撑流程**，不嵌入任何主业务流程的审批链路，评审结果（分数 + 意见）作为参考依据。

## 设计理念

- **解耦**：评审独立运转，不阻塞主流程
- **复用**：同一套评审流程可服务需求征集、立项论证、项目验收等多个阶段
- **参考**：评审结果不直接决定审批结论，最终决策权在主流程审批角色手中

## 服务场景与结果使用方式

| 主业务阶段 | 评审对象 | 结果使用方式 |
| --- | --- | --- |
| [[需求征集模块]] | 二级单位提交的需求 | 供信办管理员筛选需求时参考 |
| [[立项论证模块]] | 申报书及建设方案 | 供论证结论判定与领导小组审定参考 |
| [[项目验收模块]] | 验收材料 | 供验收结论判定参考 |
| 其他扩展场景 | 按需确定 | 关联至对应项目供审批参考 |

## 独立流程步骤（5 阶段）

### 阶段一：评审组织
1. 信办管理员选择需要评审的项目（可跨模块）
2. 选择专家队伍并提交信办领导审批
3. 信办领导确认（驳回则重新选择）

### 阶段二：评审邀请
- 系统发送邀请 → 专家接受/拒绝
- 拒绝或超时未确认 → 通知信办管理员重新选择
- 接受 → 生成评审待办

### 阶段三：评审执行
- 到约定时间，专家参与评审（线上/线下）
- 专家给出三种意见之一：**通过 / 不通过 / 退回修改**
- 专家按评审维度打分
- 系统汇总生成评审结果

### 阶段四：退回修改（仅在评审意见为"退回修改"时触发）
- 项目负责人业务页面生成「待修改」待办
- 按时修改 → 同步给专家重新评审
- 超时未修改 → 自动标记「不通过（超时未修改）」
- 超时不通过与专家评审不通过**分别记录原因**

### 阶段五：结果关联
- 评审结果（分数 + 意见 + 通过/不通过状态）自动关联至项目
- 主流程审批页面可查看作为参考
- 评审结果存档，支持历史查询（同一项目可有多次评审记录）

## 核心状态

```
待组织 → 专家队伍待确认 → 邀请已发送 → 评审待办 → 评审中 → 评审完成
                                        ↘ 待修改 ↗
                                              ↘ 超时未修改（不通过）
```

## 评审结果数据结构

| 字段 | 说明 |
| --- | --- |
| 评审 ID | 系统自动生成 |
| 关联项目 ID | 被评审的项目/需求唯一标识 |
| 触发场景 | 需求征集 / 立项论证 / 项目验收 / 其他 |
| 评审发起人 | 信办管理员 |
| 专家列表 | 参与评审的专家名单 |
| 各专家分数 | 按维度分项分数 |
| 综合分数 | 汇总/加权平均 |
| 各专家意见 | 通过 / 不通过 / 退回修改 + 文字 |
| 最终结论 | 通过 / 不通过 / 不通过（超时未修改） |
| 评审时间 | 时间戳 |
| 评审轮次 | 第几次评审 |

## 业务规则（BR-E01 ~ BR-E09）

| 编号 | 规则 |
| --- | --- |
| BR-E01 | 专家评审为独立流程，结果作为参考，不直接决定审批结论 |
| BR-E02 | 同一项目可发起多次评审，每次独立记录 |
| BR-E03 | 专家可给出三种评审意见：通过、不通过、退回修改 |
| BR-E04 | 退回修改后项目负责人有限期修改窗口，超时视为不通过 |
| BR-E05 | 超时不通过与专家评审不通过须分别记录原因 |
| BR-E06 | 专家拒绝或超时未确认邀请时须通知信办管理员重新选择 |
| BR-E07 | 专家队伍须经信办领导确认后方可发送邀请 |
| BR-E08 | 评审结果自动关联至对应项目，主流程审批页面可查看 |
| BR-E09 | 评审结果存档支持历史查询 |

## 论证阶段专家规格（保留，来自 [[立项论证模块]] 子流程 C）

V1.1 中立项论证专家论证会（子流程 C）仍沿用以下专家规格，与独立评审流程并行存在：

- **重大/中型项目**：≥ 5 名专家，须含校外专家
- **小型/微型项目**：≥ 3 名专家
- **重大项目（≥ 100 万设备）**：须有实验室建设与设备管理处人员列席
- **重大项目**：须有财务部人员列席
- **论证结论**：通过 / 修改后通过 / 不通过
- **二次论证不通过 → 锁定 1 年**（第十六条，BR-13）

## 验收阶段专家规格（来自 [[项目验收模块]] 子流程 M）

- **重大项目（≥ 500 万）**：校外专家须超过总人数的一半
- **重大项目（< 500 万）**：校外专家不少于 2 人
- **中型/小型/微型项目**：按论证阶段专家规格执行
- **验收评审维度**：9 维度（建设目标达成度、技术指标、运行效果、用户体验、数据对接共享、使用培训、维保任务、网络安全、经费使用）

## 260323 会议细化要求（独立流程下仍适用）

| 项 | 说明 |
| --- | --- |
| 评审方式 | 线上 / 线下（线下需填写会议地点） |
| 抢单模式 | 通知名额 > 响应名额，优先响应 |
| 专家问答 | 评审页面支持专家向项目负责人提问（不含敏感信息） |
| 意见可见性 | 专家评审意见经信息办审核后，项目负责人方可见 |
| 专家黑名单 | 系统维护独立存储的黑名单 |
| 行为记录 | 记录评审页面操作时间，识别不当行为；评审前须阅读确认评审须知 |

## 260409 会议细化要求

| 项 | 说明 |
| --- | --- |
| 多项目评审 | 专家标签须涵盖所有项目标签中的任意一个；评审规则按最高级别项目执行 |
| 优先响应模式 | 与 260323 抢单模式一致，进一步明确；专家不足可点击"邀请专家"重新发起 |
| 留言讨论 | 专家与项目负责人在评审阶段可针对项目留言讨论 |
| 材料修改 | 项目负责人可修改论证材料，需提交修改摘要说明修改点 |
| 意见展示决定权 | 最终评审意见由信息办管理员决定是否展示给二级单位 |
| 手写签名 | 新增专家评审意见手写签名功能，手机端完成 |

## 专家数据规范（来自 [[阶段五专家评审设计]]）

专家核心字段：`id / name / title / dept / category（技术/业务/用户）/ isExternal / phone / status`
黑名单记录独立存储，不混入专家列表。

## 专家标签体系（来自 [[专家库标签]]）

专家标签用于分类匹配（260409 会议规则：专家标签须涵盖项目标签中的任意一个）。原始数据经去重 + 语义合并后共 **30 个标准标签**，分两类：

**职能标签（6 个）**：教学、学生管理、服务管理、科研、财务、其他

**专业领域标签（24 个）**：计算机科学与技术、教育技术学、通信网络、数据科学、软件工程、人工智能、管理信息系统网络通信与安全、合成生物学、机电一体化、物理、迁移学习、计算机视觉、管理科学与工程、创新创业、思想政治教育、管理、规划、学科、学术管理、学科建设、数据管理、工程管理、招标采购、机器学习、智能制造

合并记录：「计算机科学/计算机科学技术/计算机/计算机应用/计算机技术」→ 计算机科学与技术；「教育技术」→ 教育技术学

## Demo 实现流程（来自代码分析，2026-04-17）

> 以下内容来源于 demo 代码（review.js / expert.js / data.js），反映当前演示版本的实际交互流程。

### 总览

```
Step 1  发起评审（info-admin / info-leader）4步向导
         ↓
Step 2  信息办领导确认专家名单（info-leader 独占）
         ↓
Step 2.5a  专家响应邀请（expert）
         ↓
Step 3  专家阅读评审须知并确认（门控页）
         ↓
Step 4  专家填写评审意见 + 结论
         ↓
         ├── 通过          → passed（进入审定）
         ├── 退回修改      → rework-pending
         │                    ↓
         │               项目负责人提交修改材料
         │                    ↓
         │               专家重新评审（新一轮）
         │               超时未修改 → timeout-rejected（BR-E05）
         └── 不通过        → rejected（二次不通过 → 项目冻结一年）
```

### Step 1：发起评审（4步向导）

操作角色：`info-admin` / `info-leader`，入口：`review-launch`

| 步骤 | 填写内容 |
| --- | --- |
| Step 0 基础信息 | 关联项目、评审类型（立项论证/验收评审/变更论证）、评审方式（线上/线下）、计划日期、地点（线下必填）、评审说明 |
| Step 1 评审规则 | 选规则模板、配置评审维度权重（论证4维度/验收9维度）、查看流程节点 |
| Step 2 选择专家 | 系统根据项目标签智能排序推荐；须满足 BR-05 |
| Step 3 信息确认 | 汇总确认后"提交领导确认" |

**BR-05 项目级别与专家人数要求：**

| 预算区间 | 项目级别 | 最低专家数 | 额外要求 |
| --- | --- | --- | --- |
| < 20 万 | 微型 | 3 名 | — |
| 20–99 万 | 小型 | 3 名 | — |
| 100–199 万 | 中型 | 5 名 | — |
| ≥ 200 万 | 重大 | 7 名 | 须实验室处 + 财务部列席，报领导小组审定 |

约束：总人数须为奇数，校外专家 ≥ 1/3。

### Step 2：信息办领导确认专家名单

操作角色：`info-leader`，入口：`expert-confirm`

- 查看项目摘要 + 推荐专家列表，再次核验 BR-05
- **确认** → 系统自动向所有专家发送评审邀请
- **退回** → 填写原因，返回给 info-admin 重新选人

### Step 2.5a：专家响应邀请

操作角色：`expert`，入口：`expert-respond`

邀请卡片含：项目基本信息、评审安排（时间/地点/形式）、回复截止倒计时、**利益冲突声明（必填）**。

| 操作 | 结果 |
| --- | --- |
| 接受邀请 | status → 已确认，进入填写意见环节 |
| 拒绝邀请（填原因） | status → 已拒绝，系统通知 info-admin 补选专家 |
| 超时未响应（3天提醒/5天自动） | status → 超时自动拒绝，系统通知补选 |

**专家邀请状态机：**

```
待回复
  ├─ 接受 → 已确认
  ├─ 拒绝（填原因）→ 已拒绝 → 补选专家
  └─ 超时（5天）→ 超时自动拒绝 → 补选专家
```

### Step 3：阅读评审须知（门控页）

操作角色：`expert`，入口：`review-opinion` 首次进入时触发

- 展示评审管理规范全文（260323 会议要求）
- 勾选"已认真阅读并承诺遵守评审纪律"，系统记录确认时间戳
- 确认后进入正式填写页；同一评审仅需确认一次

### Step 4：填写评审意见

操作角色：`expert`，入口：`review-opinion`

**一、综合评分**（每项 1–10 分）

- 论证评审：4 个维度
- 验收评审：9 个维度（建设目标达成度、技术指标、运行效果、用户体验、数据对接共享、使用培训、维保任务、网络安全、经费使用）
- 每个维度含权重百分比，维度数据来自 `DATA.reviewDimensions`

**二、综合意见**（文本，必填）

**三、修改建议**（文本，选填）

**四、评审结论（BR-E03）**

| 结论 | 额外要求 | 后续动作 |
| --- | --- | --- |
| 通过 | — | 计入加权总分，汇总后进入审定 |
| 退回修改 | 必填修改要求 + 修改截止日期 | status → `rework-pending` |
| 不通过 | — | 计入加权总分，汇总结论为不通过 |

### Step 4a：退回修改后续（BR-E04 / BR-E05）

**项目负责人**（`project-manager`，入口：`review-rework`）：

- 查看修改要求详情 + 截止倒计时
- 填写修改摘要 + 上传修改材料
- 提交后同步给专家重新评审（新一轮）

**超时处理（BR-E05）**：

- 超出截止日期 → 系统自动标记 `timeout-rejected`
- 超时不通过与专家评审不通过**分别记录原因**，区分归档

### Demo 评审状态全集

| status 值 | 显示标签 | 含义 |
| --- | --- | --- |
| `in-progress` | 进行中 | 评审进行中，专家待填写意见 |
| `passed` | 已通过 | 评审结论通过 |
| `rejected` | 未通过 | 评审结论不通过 |
| `rework-pending` | 退回修改中 | 等待项目负责人提交修改材料 |
| `timeout-rejected` | 不通过（超时未修改） | 退回修改后超期未提交（BR-E05） |

### 角色操作权限汇总

| 角色 | 操作 |
| --- | --- |
| info-admin | 发起评审（4步向导）、查看全部评审列表 |
| info-leader | 发起评审 + **确认专家名单**（独占） |
| expert | 响应邀请、确认评审须知、填写意见 |
| project-manager | 查看退回修改要求、提交修改材料 |
| 其他角色 | 只读查看评审列表 |
