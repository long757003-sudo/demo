# Roadmap: 西南大学信息化项目全生命周期管理系统 Demo

**Created:** 2026-04-12
**Milestone:** v1 Demo

## Overview

本路线图覆盖 Demo 原型的 6 个核心业务模块，沿项目真实生命周期顺序交付：需求征集 → 立项论证 → 专家评审 → 招采实施 → 验收运维 → 系统管理。每个阶段产出可独立演示的 OpenSpec 变更集，演示结束时可完整走通从需求提出到运维交付的全流程。Phase 0（基础框架 + 通知模板）已完成，路线图从 Phase 1 开始。

## Phases

- [ ] **Phase 1: 需求征集模块** - 信息办发起征集到单位领导审批完成的端到端流程
- [ ] **Phase 2: 立项论证模块** - 项目申报、审批、立项通知的完整流程
- [ ] **Phase 3: 专家管理&评审模块** - 专家库维护、发起评审、专家填写意见的完整流程
- [ ] **Phase 4: 项目招采&实施模块** - 采购管理、合同台账、实施进展及变更终止的完整流程
- [ ] **Phase 5: 项目验收&运维模块** - 内部初验、正式验收、运维记录和故障工单的完整流程
- [ ] **Phase 6: 通知&日志&系统管理模块** - 通知全链路、操作日志、用户权限及流程配置

## Phase Details

### Phase 1: 需求征集模块
**Goal**: 演示从信息办发起需求征集、单位填报需求、排序审批，到信息办遴选的完整闭环
**Depends on**: Phase 0 (已完成)
**Requirements**: DEM-01, DEM-02, DEM-03, DEM-04, DEM-05, DEM-06, DEM-07
**OpenSpec Changes** (1 plan ↔ 1 change，命名以 GSD plan 为权威):
  - `demand-data-foundation` (01-01) — DATA.tagLibrary / DATA.demandUsers / roleDisplayName 建立 + tag-library 视图（标签库管理）
  - `demand-collection-launch` (01-02) — 信息办管理员发起征集配置页 + 跳 notification-create 预填联动（DEM-01）
  - `demand-form-fill` (01-03) — 单位系统管理员授权指派页 + 项目负责人需求申请表（DEM-02, DEM-03；T3 含暂存/提交）
  - `demand-sort-review` (01-04) — 单位上下移排序 + 单位领导 T4 审批详情页（DEM-04, DEM-05，不用拖拽库）
  - `demand-selection` (01-05) — 信息办遴选（Drawer 展示 BR-04 六类不予支持原因）+ 需求列表 T2（DEM-06, DEM-07）
**Success Criteria** (what must be TRUE):
  1. 切换到「信息办管理员」角色，可进入发起需求征集页面，配置时间范围和通知范围后提交，页面自动跳转到通知预填页
  2. 切换到「单位系统管理员」角色，可看到征集通知并为本单位指派填报人
  3. 切换到「项目负责人」角色，可填写需求申请表并暂存/提交，表单字段完整
  4. 切换到「单位系统管理员」角色，可对本单位需求拖拽排序并提交单位领导审批
  5. 切换到「单位领导」角色，可在 T4 详情页查看需求排序并填写审批意见通过或退回
  6. 切换到「信息办管理员」角色，可在遴选页对每条需求标记支持/不支持，选择不支持时显示 BR-04 六类原因提示
  7. 需求列表（T2）可按状态和单位筛选，反映各需求的当前处理状态
**Plans**: 01-01, 01-02, 01-03, 01-04, 01-05（执行结果见 .planning/phases/01-需求征集模块/01-0x-SUMMARY.md）
**UI hint**: yes

### Phase 2: 立项论证模块
**Goal**: 演示项目负责人填报申报书、信息办审批、信息办领导下达立项通知的完整立项流程
**Depends on**: Phase 1
**Requirements**: PROJ-01, PROJ-02, PROJ-03, PROJ-04
**OpenSpec Changes**:
  - `proposal-form` — 项目申报书填报页（T3，含建设目标/技术方案/预算明细/实施计划）
  - `project-approval` — 信息办立项审批详情页（T4，查看申报书 + 审批意见 + 通过/退回/提交领导小组 BR-09）
  - `project-notice` — 立项通知书填写页（T3，确认经费）+ 申报书列表（T2，按项目分级标色）
**Success Criteria** (what must be TRUE):
  1. 切换到「项目负责人」角色，可填写完整申报书（四大板块字段均可输入）并提交
  2. 切换到「信息办管理员」角色，可在审批详情页查看申报书全文，执行通过、退回或提交领导小组操作，且 BR-09 提交领导小组条件有说明提示
  3. 切换到「信息办领导」角色，可填写并下达立项通知书，确认项目经费
  4. 申报书列表（T2）按项目分级以不同颜色标色，可区分校级/院级/部门级项目

**UI hint**: yes

### Phase 3: 专家管理&评审模块
**Goal**: 演示专家库维护、发起评审（含规则校验）、专家填写评审意见的完整专家评审流程
**Depends on**: Phase 2
**Requirements**: EXP-01, EXP-02, EXP-03, EXP-04, EXP-05, EXP-06, EXP-07
**OpenSpec Changes**:
  - `expert-library` — 专家库列表（T2，按技术/业务/用户 × 校内/校外筛选，新增/编辑）+ 黑名单列表（T2）+ 邀请记录（T2）
  - `review-launch` — 发起评审页（T3，选专家时自动校验 BR-05 回避/比例规则，领导确认后发送邀请）
  - `review-opinion` — 专家填写评审意见页（T3，五维度打分 + 论证结论，BR-06 二次论证逻辑展示）
  - `my-reviews` — 我的评审任务列表（T2，论证/验收待办）+ 评审统一列表（T2，Tab 切换论证/验收）
**Success Criteria** (what must be TRUE):
  1. 切换到「信息办管理员」角色，可在专家库列表按技术/业务/用户类型和校内/校外组合筛选，可新增和编辑专家，可查看黑名单和邀请记录
  2. 切换到「信息办管理员」角色，可发起评审并选择专家，选择违反 BR-05（回避或比例不足）时页面有明确校验提示，满足条件后可提交领导确认
  3. 切换到「专家」角色，可在我的评审任务中看到待办评审，进入后可对五个维度打分并给出论证结论
  4. 当论证结论触发 BR-06 二次论证条件时，页面展示相应提示说明
  5. 评审列表（T2）以 Tab 分隔论证和验收任务，状态清晰可筛选

### Phase 4: 项目招采&实施模块
**Goal**: 演示采购管理、合同台账、实施进展汇报及变更/延期/终止申请的完整招采实施流程
**Depends on**: Phase 3
**Requirements**: PROC-01, PROC-02, PROC-03, IMPL-01, IMPL-02, IMPL-03, IMPL-04, IMPL-05
**OpenSpec Changes**:
  - `procurement-management` — 采购管理详情页（T4，调研填报 ≥3 家校验 BR-17，Mock 招采系统接口数据展示）
  - `contract-ledger` — 合同台账列表（T2，含到期提醒标记）+ 经费管理列表（T2，合同进度款状态 + 年度预算总览，只读）
  - `implementation-progress` — 实施进展汇报页（T3，按合同支付节点提交材料，BR-20 汇报频率提示）
  - `change-delay-terminate` — 延期申请页（T3，BR-14 超半年校验）+ 变更申请页（T3，BR-22 触发专家论证提示）+ 终止申请页（T3，BR-24 五种情形单选）+ 项目详情页（T4，生命周期进度条 + 审批流时间轴 + 操作记录 Tab）
**Success Criteria** (what must be TRUE):
  1. 切换到「项目负责人」角色，可在采购管理页填写调研信息，填报供应商少于 3 家时触发 BR-17 提示，页面展示 Mock 招采系统返回数据
  2. 合同台账列表（T2）展示合同列表，临近到期合同有视觉提醒；经费管理页以只读方式展示进度款支付状态和年度预算使用情况
  3. 切换到「项目负责人」角色，可按合同节点提交实施进展材料，页面展示 BR-20 汇报频率提示
  4. 可分别发起延期申请（延期超半年时 BR-14 校验报错）、变更申请（提交时弹出 BR-22 触发专家论证提示）、终止申请（必须单选一种终止情形）
  5. 项目详情页（T4）完整展示生命周期进度条（各节点高亮当前阶段）、审批流时间轴（各节点操作人和时间）和操作记录 Tab

## Dependencies

```
Phase 0 (完成) → Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5 → Phase 6
```

- Phase 1 依赖 Phase 0：需要基础框架（12 角色切换、页面模板、工作台）和通知模板结构
- Phase 2 依赖 Phase 1：立项论证以需求遴选结果为前提，申报书关联已遴选需求
- Phase 3 依赖 Phase 2：专家评审以立项通过的项目为触发对象
- Phase 4 依赖 Phase 3：招采流程在项目论证通过后启动；变更申请（IMPL-03）触发的专家论证复用 Phase 3 的评审流程
- Phase 5 依赖 Phase 4：验收以实施完成为前提，运维以验收通过为前提
- Phase 6 可并行开发部分内容（通知模板已完成），但完整通知链路需等各模块业务操作确定后联调
