# 需求征集模块

[[全生命周期管理系统]] 第一步。权威版本：[[业务流程说明书V1.1]]（BPD-2026-001 V1.1）。

## 模块概述

信办管理员创建征集信息并经信办领导审批后发布；各二级单位组织填报和内部审批后提交信息办；信办管理员可独立组织 [[专家评审规则|专家评审]]（评审结果作为筛选参考，不直接决定需求去留）；最终由信办管理员筛选并提交信办领导审核，通过后需求状态变为已通过，触发 [[立项论证模块]]。

## 业务流程（V1.1）

### 阶段一：信息办发送需求征集信息

1.1 信办管理员创建需求征集信息（范围、时间、填报说明）
1.2 提交信办领导审批
1.3 信办领导审批
    - 通过 → 系统按要求发送征集信息和通知
    - 不通过 → 退回信办管理员修改（返回 1.1）

### 阶段二：二级单位提交需求

2.1 系统推送征集通知至单位管理员
2.2 单位管理员指派项目负责人
2.3 项目负责人填写并提交《需求申请表》（可提交多份）
2.4 单位管理员对本单位需求排序整理，提交单位领导审批
2.5 二级单位分管领导审批（审批时可调整优先级排序）
    - 通过 → 推送至信息办
    - 不通过 → 退回修改，可重新提交

### 阶段三：信息办筛选需求

> 专家评审（[[专家评审规则|独立流程]]）可在本阶段之前或并行组织，结果作为筛选参考。

4.1 信办管理员结合专家评审结果（如有）进行筛选
4.2 确定筛选结果并提交信办领导审核（未选中视为不通过）
4.3 信办领导审核
    - 通过 → 需求状态「已通过」，触发 [[立项论证模块]]
    - 不通过 → 需求状态「不通过」

## 核心状态

```
征集信息待审批 → 征集信息已发布 → 需求填报中 → 排序完成·待审批
→ 单位审批通过（推送至信息办）→ 待筛选 → 已通过 / 不通过
```

## 业务规则（BR-01 ~ BR-09）

| 编号 | 规则 | 来源 |
| --- | --- | --- |
| BR-01 | 征集信息发布前须经信办领导审批 | V1.1 调整 |
| BR-02 | 一个项目负责人可提交多份需求申请 | 260409 会议 |
| BR-03 | 单位领导审批时可调整需求优先级排序 | 260409 会议 |
| BR-04 | 单位领导驳回后可退回修改并重新提交，非直接终止 | V1.1 调整 |
| BR-05 | 专家评审为独立流程，评审结果作为筛选参考，不直接决定需求去留 | V1.1 调整 |
| BR-06 | 专家可给出三种评审意见：通过、不通过、退回修改 | V1.1 调整 |
| BR-07 | 退回修改后项目负责人有限期修改窗口，超时视为不通过 | V1.1 调整 |
| BR-08 | 超时不通过与专家评审不通过须分别记录原因 | V1.1 调整 |
| BR-09 | 筛选环节未被选中的需求视为不通过 | V1.1 调整 |

## 核心功能

### 需求申请表字段（260409 更新）
- 新增 **"摘要"** 必填字段，审批页面同步展示
- 新增**标签选择**功能（从系统标签库中选择）
- 系统新增**标签库模块**
- 支持上传文件后**自动识别内容并填充**至页面
- 允许被授权的项目负责人提交**多份需求申请表**

### 自动初筛引擎（6条规则，对应第十三条）

> V1.1 简化后，初筛引擎作为筛选辅助工具继续保留；筛选最终由信办管理员人工确认。

| 规则 | 初筛逻辑 | 标记结果 |
|------|---------|---------|
| 已建/在建项目重复申报 | 匹配历史项目库，检查同名/高度相似项目 | 疑似重复 |
| 需求不明确/预算背离 | 校验必填字段完整性 | 格式不通过 |
| 与现有系统功能重叠 | 匹配现有系统功能标签库，关联度>阈值且无差异说明 | 疑似重叠 |
| 技术路线过时 | 扫描"技术过时关键词库" | 技术路线存疑 |
| 已被否决且无新理由 | 匹配历史被否决项目库 | 疑似重复否决 |
| 不符合学校其他规定 | 预留合规规则引擎接口 | — |

### 主要数据表

- `collection_batch`：征集批次
- `requirement_application`：需求申请表（含初筛/复核结果字段）

## 历史沿革

| 项 | V1.0（260409 之前） | V1.1（本版） |
| --- | --- | --- |
| 征集信息发布 | 信办管理员直发 | 经信办领导审批后发布 |
| 单位领导驳回 | 终止流程 | 退回修改，可重新提交 |
| 专家评审定位 | 嵌入主流程，结论直接决定去留 | 独立流程，仅作筛选参考 |
| 退回修改机制 | 无 | 专家可退回，项目负责人限期修改 |
| 超时未修改 | 无 | 视为不通过（独立记录原因） |
| 冷却期 | 评审不通过进入 1 年冷却期 | **取消** |
| 筛选环节 | 遴选 → 审定 → 入需求库 | 筛选 → 审核 → 已通过/不通过 |
