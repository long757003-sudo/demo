# 通知矩阵 — 各角色待办 / 待阅通知设计

> 覆盖系统全生命周期 6 大模块、13 个里程碑、11 类角色的所有关键操作节点。
>
> **待办通知**：收到后需主动操作，未处理则持续提醒，超期可自动升级。
> **待阅通知**：告知类，知晓即可，无需操作回复。

---

## 通知渠道策略

| 渠道 | 使用场景 |
|------|---------|
| **站内信** | 所有通知的基础渠道，100% 覆盖 |
| **邮件** | 正式节点（立项、验收、终止）、外部角色（专家）、驳回/锁定类通知 |
| **钉钉** | 高优先级待办（需立即处理）、SLA 超期告警、领导审批 |
| **短信** | 仅限 P0 故障及 SLA 超期升级场景 |

## 通知触发方式

| 触发类型 | 示例 | 实现方式 |
|---------|------|--------|
| **操作触发** | 提交申请 → 立即通知审批人 | 业务逻辑层同步/异步发送 |
| **状态变更触发** | 审批通过/驳回 → 通知申请人 | 工作流引擎 Flowable 回调 |
| **定时触发** | 汇报周期到达、SLA 超期监控 | Spring Scheduled Task / RabbitMQ 延迟队列 |
| **系统规则触发** | 自动初筛完成、项目锁定 | 规则引擎计算后异步发送 |
