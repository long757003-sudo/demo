# 项目实施模块

[[全生命周期管理系统]] 第四步。权威版本：[[业务流程说明书V1.1]]（BPD-2026-004）。

## 模块概述

合同签订后进入项目实施阶段。项目负责人组建工作小组、制定实施计划并推进建设；承建方执行阶段性建设任务；实施过程中可发起变更、延期、终止申请。建设完成后触发 [[项目验收模块]]。

## 主流程（8 步）

1. 接收「合同签订」触发，启动实施准备
2. 组建工作小组（5 类成员）→ 状态「实施准备中」
3. 制定实施计划（甘特图）→ 项目启动 → 状态「实施中」
4. 承建方执行阶段性建设：调研 → 设计 → 部署 → 试运行
5. 定期进度汇报（**子流程 G**），循环执行
6. 变更 / 延期 / 终止申请按需触发（**子流程 H / I / J**）
7. 建设完成，项目负责人与承建方确认完工
8. 提交验收准备材料 → 状态「建设完成」 → 触发 [[项目验收模块]]

## 子流程

### G：进度汇报（按级别）

| 级别 | 频率 | 汇报对象 |
| --- | --- | --- |
| 重大 / 中型 | 每周 | 用户单位 + 信息办 |
| 重大 / 中型 | 每月 | 分管校领导 |
| 重大 / 中型 | 每季度 | 领导小组 |
| 小型 | 每半月 | 用户单位 + 信息办 |
| 微型 | 按需 | 信息办备案 |

### H：变更申请

- 变更类型：建设内容 / 技术方案 / 预算 / 周期
- 须说明客观原因
- 信办管理员审核，必要时组织专家论证（参照 [[立项论证模块]] 子流程 C）
- 通过 → 系统更新方案，状态「实施中（变更后）」；驳回 → 维持原方案

### I：延期申请

- 须**提前 30 个工作日**提交（书面）
- 信办管理员审核
- 批准且 ≤ 半年 → 状态「实施中·已延期」
- 批准且 > 半年 → 自动标记「负面清单」+ 上报领导小组
- 不批准 → 维持原期限

### J：项目终止

- 终止原因：国家政策变化 / 学校战略调整 / 资金短缺 / 厂商变故 / 技术落后
- 流程：信办管理员审核 → 信办领导审批 → 费用清算（合同管理员参与）→ 资产清查处置 → 资料归档 → 状态「已终止」
- 终止后项目不再流转至验收

## 核心状态

```
实施准备中 → 实施中 → 建设完成 / 已终止
```

## 业务规则（BR-21 ~ BR-25）

| 编号 | 规则 | 来源 |
| --- | --- | --- |
| BR-21 | 工作小组须包含 5 类成员 | 260409 会议 |
| BR-22 | 延期申请须提前 30 个工作日提交 | 260409 会议 |
| BR-23 | 延期超半年标记「负面清单」并上报领导小组 | 第三十一条 |
| BR-24 | 变更必要时须组织专家论证 | 260409 会议 |
| BR-25 | 终止时须完成费用清算、资产清查、资料归档 | 260409 会议 |

## 工作小组构成（第二十七条）

5 类成员：单位分管领导、项目负责人（用户单位）、信息办分管领导、信息办对接人、承建方项目经理。

## 主要数据表

- `project_team`：工作小组
- `implementation_plan`：实施计划（甘特图数据）
- `progress_report`：进度汇报
- `change_request`：变更申请
- `extension_request`：延期申请（含 `is_negative_list` 字段）
- `project_termination`：项目终止
