# Demo 设计规格（2026-03-26）

**文件用途**：可点击原型 Demo 的设计规格，用于与用户确认功能和业务流程细节。
**来源**：《西南大学信息化项目管理办法（试行）》西校〔2025〕39号

## 关键要点

### 技术方案
| 项目 | 决策 |
|------|------|
| Demo 形态 | 可点击原型（假数据，无真实后端） |
| 技术栈 | 纯 HTML / CSS / JavaScript，无构建工具 |
| 文件结构 | `index.html`（登录）+ `app.html`（主 Shell）+ `shared/`（nav/router/data/style） |
| 数据存储 | `localStorage`（角色状态、表单草稿） |
| 部署方式 | 直接复制文件夹，零依赖 |

所有 40 个视图均定义为函数内置于 `app.html`，通过 hash 路由切换。

### 演示案例
> 项目名称：本科教学质量分析平台 | 申请单位：教务处 | 预算：85 万元（小型项目）
> 适用路径：小型项目完整流程——专家 3 人论证、领导小组办公室审定、挂网采购

### 角色定义（12 个）
与 [[角色体系]] 对照，本 Demo 明确列出 12 个角色：
1. 数智化建设领导小组
2. 领导小组办公室
3. 信息办领导
4. 信息办管理员
5. 用户单位分管领导
6. **用户单位系统管理员**（在 Demo 中独立角色，负责指派填报权限）
7. 用户单位项目负责人
8. 用户单位项目协助人
9. **合同管理员**（专职合同台账管理）
10. **财务管理员**（只读查看经费使用，不操作付款）
11. 专家委员会
12. 系统管理员

### 通知联动机制（4 类通知）
详见 [[系统视图规范]] 通知联动节。立项环节有两种易混淆通知：

| 通知类型 | 发送时机 | 发送人 | 接收人 | 触发方式 |
|---------|---------|--------|--------|---------|
| 需求征集通知 | 需求征集发起时 | 信息办管理员 | 各单位系统管理员 | 手动跳转页面填发 |
| 立项申请通知书 | 需求遴选通过后 | 信息办管理员 | 被选需求的项目负责人 | 手动跳转页面填发 |
| 专家评审邀请 | 信息办领导确认专家名单后 | 系统自动 | 受邀专家 | 系统自动发送，不经通知管理页 |
| 立项通知书 | 领导审定通过后 | 信息办管理员 | 立项项目负责人 | 手动跳转页面填发 |

### 防纠纷设计
通知发送详情页记录每位收件人的送达时间和已读时间，支持导出为 PDF/Excel 作为凭证。
