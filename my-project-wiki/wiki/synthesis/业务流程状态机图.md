# 业务流程状态机图

[[全生命周期管理系统]] 六大模块完整状态机，以 260409 会议版本为准。每个模块独立展示参与角色与泳道，子流程单独拆出。

---

## 角色速查

| 缩写 | 全称 | 所属机构 |
|-----|------|--------|
| 信办管理员 | 信息办管理员（信息办专员/林科长） | 信息办 |
| 信办领导 | 信息办领导 | 信息办 |
| 单位管理员 | 用户单位系统管理员（二级单位管理员） | 二级单位 |
| 项目负责人 | 用户单位项目负责人（经办人） | 二级单位 |
| 单位领导 | 用户单位分管领导（二级单位负责人） | 二级单位 |
| 专家 | 专家委员会（校内/校外专家） | 外部/内部 |
| 领导小组 | 数智化建设领导小组 / 领导小组办公室 | 学校 |
| 合同管理员 | 采购与招投标管理中心合同管理员 | 采购中心 |
| 承建方 | 项目承建/服务厂商 | 外部 |

---

## 全局流程总览

```
需求征集 ──→ 立项论证 ──→ 项目招采 ──→ 项目实施 ──→ 项目验收 ──→ 项目运维
                                              │
                                              └──→ [已终止]（实施阶段任意时点可终止）
```

**全局冷却期约束**

| 触发场景 | 锁定时长 |
|---------|---------|
| 需求征集专家评审不通过 | 1 年后可再次提交 |
| 立项论证二次不通过 | 1 年后系统自动解锁 |
| 项目验收二次不合格 | 半年后系统自动解锁 |

**全局自动失效监控**

| 触发条件 | 系统动作 | 来源条文 |
|---------|---------|--------|
| 已立项超 6 个月未启动采购 | 标记 [失效·需重新论证] | 第二十二条 |
| 已立项超 1 年未签订合同 | 标记 [失效·需重新论证] | 第二十二条 |

## 模块一：需求征集

**参与角色**：信办管理员、信办领导、单位管理员、项目负责人、单位领导、专家

### 主流程（按角色泳道）

| 步骤  | 操作角色      | 动作 / 当前状态                                          | 分支条件                    |
| --- | --------- | -------------------------------------------------- | ----------------------- |
| ①   | **信办管理员** | 发布需求征集通知 + 公告，设定批次开放时间 → `[征集批次·开放中]`              |                         |
| ②   | **单位管理员** | 接收通知，指派项目负责人填报权限                                   |                         |
| ③   | **项目负责人** | 填写《需求申请表》（必填：摘要、标签；支持上传文件自动识别填充；可提交多份） → `[需求填报中]` |                         |
| ④   | **单位管理员** | 对本单位全部需求排序整理，提交领导审批 → `[排序完成·待审批]`                 |                         |
| ⑤   | **单位领导**  | 审批（审批时可再次调整优先级排序）                                  | 驳回 → `[已驳回]`（终止）；通过 → ⑥ |
| ⑥   | **信办管理员** | 决定是否组织专家评审 → `[单位审批通过]`                            | 跳过 → 直接 ⑨；组织 → 子流程 A    |
| ⑦   | **信办领导**  | 确认专家队伍（子流程 A 入口）                                   | → ⑧                     |
| ⑧   | **专家**    | 在线评审需求（详见子流程 A）→ `[专家评审中]`                         | 通过 → ⑨；不通过 → `[1 年冷却期]` |
| ⑨   | **信办管理员** | 筛选需求名单 → `[待遴选]`                                   | 未选中 → `[遴选未通过]`；选中 → ⑩  |
| ⑩   | **信办领导**  | 确认审定 → **`[入需求库]`**                                | → 触发立项论证                |

### 子流程 A：需求专家评审（信办管理员可跳过）

| 步骤 | 操作角色 | 动作 | 分支 |
|------|---------|------|-----|
| A1 | **信办管理员** | 选择参与评审的需求项目（支持"预览库"操作；多项目时专家规格按最高级别执行） | |
| A2 | **信办管理员** | 发出邀请（邀请数 > 所需响应人数，优先响应/抢单模式） | 响应不足 → 点击"邀请专家"重新发起 |
| A3 | **信办领导** | 审批确认专家名单 | 可驳回重选 |
| A4 | **专家** | 抢单接受邀请，阅读评审须知（系统记录截屏等异常操作） | |
| A5 | **专家** | 在线评审 + 向项目负责人留言提问（不含敏感信息） | 超时未完成 → 信办介入重选专家并延期 |
| A6 | **项目负责人** | 在评审期内回复专家提问；如修改材料须提交修改摘要说明修改点 | |
| A7 | **专家** | 提交评审意见 + 手机端手写签名 | |
| A8 | **信办管理员** | 审核评审意见，决定是否展示给二级单位相关人员 | |
| A9 | **系统（自动）** | 汇总结论 | 通过/修改后通过 → 返回主流程 ⑨；不通过 → `[1 年冷却期]` |

> *（待确认）* 专家评审通过标准：多数（>50%）通过还是全员（100%）通过？

## 模块二：立项论证

**参与角色**：项目负责人、信办管理员、信办领导、专家、领导小组/办公室

### 主流程（按角色泳道）

| 步骤 | 操作角色 | 动作 / 当前状态 | 分支条件 |
|------|---------|--------------|---------|
| ① | **项目负责人** | 从需求库发起立项，填报《申报书》（建设目标、技术方案、采购清单、甘特图等）→ `[申报书填报中]` | |
| ② | **项目负责人** | 供应商调研（详见子流程 B，非单一来源采购须 ≥ 3 家） | |
| ③ | **项目负责人** | 提交申报材料（申报书 + 建设方案 + 调研报告）→ `[申报材料审核中]` | → ④ |
| ④ | **信办管理员** | 审核申报材料（规范性、完整性） | 退回 → 返回 ①；通过 → ⑤ |
| ⑤ | **信办管理员** | 组织专家论证（详见子流程 C）→ `[专家论证中]` | |
| ⑥ | **专家** | 在线打分（8 维度，1-5 分）+ 文字意见 + 手写签名 | |
| ⑦ | **系统（自动）** | 形成论证结论 → `[论证结论]` | 通过 → ⑧；修改后通过 → 子流程 D；不通过 → 子流程 E |
| ⑧ | **信办管理员** | 汇总拟建项目清单，确认优先级 → `[拟建项目清单]` | → ⑨ |
| ⑨ | **领导小组/办公室** | 审定（重大项目 → 领导小组；中/小/微型 → 领导小组办公室） | → ⑩ |
| ⑩ | **信办管理员** | 下达《立项通知书》（含采购截止日期、合同截止日期）→ **`[已立项]`** | → 触发招采模块 |

### 特殊立项通道（跳过常规论证）

| 情形 | 操作角色 | 说明 |
|-----|---------|-----|
| 预算 < 5 万 | **信办管理员** | 审批后直接立项，无需论证（第二十一条） |
| 上级要求 / 突发状况 / 学校决策会议 | **信办领导 / 领导小组** | 直接下达立项通知书 |

### 子流程 B：供应商调研（非单一来源采购必须执行）

| 步骤 | 操作角色 | 动作 |
|------|---------|------|
| B1 | **项目负责人** | 选择 ≥ 3 家供应商，在系统中录入调研信息 |
| B2 | **系统（自动）** | 生成《供应商调研情况对比报告》 |
| B3 | **项目负责人** | 确认报告，附于申报材料一并提交 |

### 子流程 C：专家论证会组织

| 步骤 | 操作角色 | 动作 | 分支 |
|------|---------|------|-----|
| C1 | **信办管理员** | 确定论证方式（线上 / 线下，线下需填写会议地点） | |
| C2 | **信办管理员** | 按级别选择专家（重大/中型 ≥ 5 名含校外；小型/微型 ≥ 3 名），发出邀请（优先响应模式） | 响应不足 → 重新邀请 |
| C3 | **信办领导** | 审批确认专家名单 | 可驳回重选 |
| C4 | **专家** | 接受邀请，阅读评审须知（系统记录操作时间，识别不当行为） | |
| C5 | **专家** | 针对项目向负责人提问（不含敏感信息） | |
| C6 | **项目负责人** | 论证期内回复专家提问；可修改材料（须提交修改摘要） | |
| C7 | **专家** | 完成 8 维度打分 + 文字意见 + 手机端手写签名 | 超时未完成 → 信办介入重选并延期 |
| C8 | **信办管理员** | 审核专家评审意见，决定对二级单位的展示范围 | → 返回主流程 ⑦ |

> 特殊要求：重大项目（≥ 100 万设备）须有实验室建设与设备管理处人员列席；重大项目须有财务部人员列席。

### 子流程 D：修改后通过（整改）

| 步骤 | 操作角色 | 动作 |
|------|---------|------|
| D1 | **项目负责人** | 按专家论证意见修改申报书 |
| D2 | **信办管理员** | 审核整改内容是否符合要求 |
| D3 | **系统（自动）** | 整改确认通过 → 进入主流程 ⑧ |

### 子流程 E：论证不通过

| 步骤 | 操作角色 | 动作 | 分支 |
|------|---------|------|-----|
| E1 | **系统（自动）** | 标记不通过，记录次数 | 第 1 次 → E2；第 2 次 → E3 |
| E2 | **项目负责人** | 申请二次论证，重新走子流程 C | |
| E3 | **系统（自动）** | 二次仍不通过 → **`[系统锁定]`**（1 年后自动解锁） | |

## 模块三：项目招采

**参与角色**：项目负责人、信办管理员、合同管理员（采购中心）

### 主流程（按角色泳道）

| 步骤 | 操作角色 | 动作 / 当前状态 | 分支条件 |
|------|---------|--------------|---------|
| ① | **项目负责人** | 根据《立项通知书》编制采购文件 → `[采购文件编制中]` | |
| ② | **项目负责人** | 提交信息办技术审核 | → ③ |
| ③ | **信办管理员** | 技术审核（技术规范一致性 / 接口标准 / 安全防护 / 数据治理）→ `[技术审核中]` | 退回 → 返回 ①；通过 → ④ |
| ④ | 见子流程 F | 按项目级别执行采购 → `[采购执行中]` | 承建方确定 → ⑤ |
| ⑤ | **项目负责人** | 拟定合同（建设周期原则上 ≤ 2 年，付款与进度挂钩）→ `[合同拟定中]` | |
| ⑥ | **信办管理员** | 合同审核 → `[合同审核中]` | 退回 → 返回 ⑤；通过 → ⑦ |
| ⑦ | **合同管理员** | 合同签订 + 备案归档 → **`[合同签订]`** | → 触发实施模块 |

> 自动监控：合同建设周期 > 2 年 → 系统自动预警。

### 子流程 F：采购执行方式（按项目级别）

| 项目级别 | 预算区间 | 采购方式 | 执行主体 |
|---------|---------|---------|---------|
| **重大** | > 200 万 | 政府采购公开招标 | 采购与招投标管理中心 |
| **中型** | 100 ~ 200 万 | 政府竞争性磋商 / 谈判 / 单一来源 / 合作创新 | 采购与招投标管理中心 |
| **小型** | 20 ~ 100 万 | 非政府采购（挂网：询比 / 磋商 / 谈判 / 直接采购） | 采购与招投标管理中心 |
| **微型** | < 20 万 | 信息办审批后自行采购 | 二级单位自行组织 |

## 模块四：项目实施

**参与角色**：项目负责人、承建方、信办管理员、信办领导、单位领导、专家（变更时可选）、领导小组

### 主流程（按角色泳道）

| 步骤 | 操作角色 | 动作 / 当前状态 | 分支条件 |
|------|---------|--------------|---------|
| ① | **项目负责人** | 组建工作小组（5 类成员：单位分管领导、项目负责人、信办分管领导、信办对接人、承建方项目经理）→ `[实施准备中]` | |
| ② | **项目负责人** | 制定实施计划（甘特图），项目正式启动 → `[实施中]` | |
| ③ | **承建方** | 阶段性建设（调研 → 设计 → 部署 → 试运行） | |
| ④ | **项目负责人** | 定期进度汇报（详见子流程 G） | 循环执行 |
| ⑤ | **项目负责人** | 如需变更 → 子流程 H | 可在实施中任意时点发起 |
| ⑥ | **项目负责人** | 如需延期 → 子流程 I（须提前 30 个工作日申请） | 可在实施中任意时点发起 |
| ⑦ | **项目负责人** | 如需终止 → 子流程 J | 可在实施中任意时点发起 |
| ⑧ | **项目负责人 + 承建方** | 建设完成，提交验收准备 → **`[建设完成]`** | → 触发验收模块 |

### 子流程 G：进度汇报频率

| 项目级别 | 汇报频率 | 汇报对象 | 高频汇报（重大/中型） |
|---------|---------|---------|------------------|
| **重大 / 中型** | 每周 | 用户单位 + 信息办 | 每月 → 分管校领导；每季度 → 领导小组 |
| **小型** | 每半月 | 用户单位 + 信息办 | — |
| **微型** | 按需备案 | 信息办 | — |

### 子流程 H：变更申请

| 步骤 | 操作角色 | 动作 | 分支 |
|------|---------|------|-----|
| H1 | **项目负责人** | 提交变更申请（类型：建设内容 / 技术方案 / 预算 / 周期），说明客观原因 | |
| H2 | **信办管理员** | 审核变更（必要时组织专家论证） | 通过 → H3；驳回 → 维持原方案，返回主流程 ④ |
| H3 | **系统（自动）** | 更新项目方案 → 继续 `[实施中]`（变更后） | → 返回主流程 ④ |

### 子流程 I：延期申请

| 步骤 | 操作角色 | 动作 | 分支 |
|------|---------|------|-----|
| I1 | **项目负责人** | 提前 30 个工作日提交延期申请（书面），说明原因 | |
| I2 | **信办管理员** | 审核延期申请 | 不批准 → 维持原期限；批准 → I3 |
| I3 | **系统（自动）** | 延期 ≤ 半年 → `[实施中·已延期]`，继续正常流程 | 延期 > 半年 → 自动标记 `[负面清单]` → 上报领导小组 |

### 子流程 J：项目终止

| 步骤 | 操作角色 | 动作 |
|------|---------|------|
| J1 | **项目负责人** | 提交终止申请（原因：国家政策变化 / 学校战略调整 / 资金短缺 / 厂商变故 / 技术落后） |
| J2 | **信办管理员** | 审核终止申请 |
| J3 | **信办领导** | 审批终止 |
| J4 | **项目负责人 + 合同管理员** | 费用清算 |
| J5 | **项目负责人** | 资产清查处置 |
| J6 | **项目负责人 + 信办管理员** | 资料归档 |
| J7 | **系统（自动）** | 项目状态更新为 **`[已终止]`** |

## 模块五：项目验收

**参与角色**：承建方、项目负责人、信办管理员、专家、信办领导

### 主流程（按角色泳道）

| 步骤 | 操作角色 | 动作 / 当前状态 | 分支条件 |
|------|---------|--------------|---------|
| ① | **承建方** | 提交验收材料（需求规格说明书、测试报告、用户手册、安全检测报告、源代码/部署文档等） | |
| ② | **系统（自动）** | 前置校验（详见子流程 K）→ `[前置校验中]` | 任一项不通过 → ❌ 禁止提交，返回 ① |
| ③ | **项目负责人** | 组织二级单位内部初验 → `[内部初验中]` | 不合格 → 子流程 L；合格 → ④ |
| ④ | **系统（自动）** | 试运行倒计时（最短 1 个月，系统强制，未满则禁止提交正式申请）→ `[试运行中]` | |
| ⑤ | **项目负责人** | 提交正式验收申请 → `[正式验收申请]` | → ⑥ |
| ⑥ | **信办管理员** | 组织验收，确定专家团队（详见子流程 M）→ `[验收评审中]` | |
| ⑦ | **专家** | 验收评审（9 维度：建设目标达成度 / 技术指标 / 运行效果 / 用户体验 / 数据对接共享 / 使用培训 / 维保任务 / 网络安全 / 经费使用） | |
| ⑧ | **信办管理员** | 形成验收结论 | 合格 → ⑨；不合格 → 子流程 N |
| ⑨ | **项目负责人 + 信办管理员** | 文档归档 + 资产移交 + 使用推广 → **`[验收通过·项目移交]`** | → 触发运维模块 |

### 子流程 K：前置校验（系统强制，缺失任一则禁止提交验收申请）

| 校验项 | 适用范围 | 不满足后果 |
|-------|---------|---------|
| 等保测评报告（第三方） | 所有项目 | ❌ 系统禁止提交 |
| 软件测评报告（第三方） | 软件开发类项目 | ❌ 系统禁止提交 |
| 试运行时长 ≥ 1 个月 | 所有项目 | ❌ 系统禁止提交 |

### 子流程 L：内部初验整改

### 子流程 P：故障工单处理

| 步骤 | 操作角色 | 动作 | 分支 |
|------|---------|------|-----|
| P1 | **项目负责人 / 用户** | 上报故障，填写基本信息 | |
| P2 | **系统（自动）** | 判定故障级别（见下表） | P0/P1 → 自动通知信办 + 领导小组 |
| P3 | **承建方** | 按级别时限响应并开始处理 | |
| P4 | **承建方** | 在处理时限内解决故障，更新工单状态 | 超时 → 升级上报 |
| P5 | **项目负责人** | 确认故障已解决，关闭工单 | |

**故障分级响应标准（第四十三条）**

| 级别 | 定义 | 响应时限 | 处理时限 | 自动上报 |
|------|------|---------|---------|---------|
| **P0·紧急** | 系统完全不可用，影响全校 | 15 分钟 | 2 小时 | 信办 + 领导小组 |
| **P1·严重** | 核心功能不可用 | 30 分钟 | 4 小时 | 信办 + 领导小组 |
| **P2·一般** | 部分功能异常 | 2 小时 | 24 小时 | — |
| **P3·轻微** | 体验问题，不影响使用 | 8 小时 | 72 小时 | — |

### 子流程 Q：数据备份（第四十四条）

| 步骤 | 操作角色 | 动作 | 分支 |
|------|---------|------|-----|
| Q1 | **系统（自动）** | 按配置执行全量 / 增量备份，异地安全存储 | 成功 → Q2；失败 → Q3 |
| Q2 | **系统（自动）** | 定期验证备份可恢复性，记录备份日志 | |
| Q3 | **系统（自动）** | 备份异常 → 自动告警 → 通知信办管理员 | |
