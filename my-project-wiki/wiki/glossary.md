## 角色术语

### 系统管理员
- 规范名：系统管理员
- 别名：`sys-admin`（代码 ID）
- 定义：负责系统全局配置、用户角色管理、流程引擎维护的管理员角色。
- 机构：信息办
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 信息办管理员
- 规范名：信息办管理员
- 别名：`info-admin`（代码 ID）、"信息办专员"（早期文档）
- 定义：负责需求征集发布、初步筛选、组织专家论证、审核、验收组织、运维监管的信息办工作人员。
- 机构：西南大学信息办
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 信息办领导
- 规范名：信息办领导
- 别名：`info-leader`（代码 ID）
- 定义：信息办主管，负责需求审批、决策看板查看、报告导出。
- 机构：西南大学信息办
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 领导小组成员
- 规范名：领导小组成员
- 别名：`leadership-group`（代码 ID）、"数智化建设领导小组"（机构全称）
- 定义：校级决策层成员，负责重大项目（>200万）审定、成效评估、全局看板查看。
- 机构：数智化建设领导小组
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 领导小组办公室
- 规范名：领导小组办公室
- 别名：`leadership-office`（代码 ID）
- 定义：挂靠党政办与信息办，负责中/小/微型项目审定、进度监控。
- 机构：党政办公室 / 信息办
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 用户单位系统管理员
- 规范名：用户单位系统管理员
- 别名：`unit-admin`（代码 ID）、"二级单位管理员"（口头简称）
- 定义：二级单位内负责指派需求填报权限、对本单位需求排序提交、分派协助人授权的管理人员。
- 机构：二级单位（如教务处、招生处等）
- 首次出现：raw/docs/2026-03-26-信息化项目全生命周期管理系统-demo-design.md

### 用户单位项目负责人
- 规范名：用户单位项目负责人
- 别名：`project-manager`（代码 ID）、"二级单位经办人"（早期文档）
- 定义：二级单位内负责需求申报、项目实施管理、验收初验、运维管理的项目执行人员。
- 机构：二级单位
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 用户单位项目协助人
- 规范名：用户单位项目协助人
- 别名：`project-assistant`（代码 ID）
- 定义：协助项目负责人填报，权限与项目负责人相同，仅限立项申报书阶段，须经分管领导审批方可添加。
- 机构：二级单位
- 首次出现：raw/meetings/260323会议纪要.md

### 用户单位分管领导
- 规范名：用户单位分管领导
- 别名：`unit-leader`（代码 ID）、"二级单位负责人"（口头简称）
- 定义：二级单位分管领导，对本单位需求和申请进行内部审批、签字确认，可对本单位需求进行优先级排序。
- 机构：二级单位
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 合同管理员
- 规范名：合同管理员
- 别名：`contract-admin`（代码 ID）
- 定义：负责合同台账管理、合同审定归档的专业管理人员。
- 机构：采购与招投标管理中心
- 首次出现：raw/docs/2026-03-26-信息化项目全生命周期管理系统-demo-design.md

### 财务管理员
- 规范名：财务管理员
- 别名：`finance-admin`（代码 ID）、"财务专员"（口头简称）
- 定义：只读查看经费使用情况（合同进度款 + 年度预算总览），不直接操作付款。
- 机构：财务部
- 首次出现：raw/docs/2026-03-26-信息化项目全生命周期管理系统-demo-design.md

### 专家委员会
- 规范名：专家委员会
- 别名：`expert`（代码 ID）、"评审专家"（场景简称）
- 定义：参与项目论证、验收评审的校内/校外专业人士，含技术类、业务类、用户类专家。
- 机构：校内 / 外部
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

## 机构与参与方术语

### 二级单位
- 规范名：二级单位
- 别名：`unit`（代码 ID）、"用户单位"（系统显示名）、"分支机构"（非规范叫法）
- 定义：西南大学下属的一级管理单位（如教务处、招生处、各学院等），是需求申报和项目执行的业务主体。
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 信息化建设办公室
- 规范名：信息化建设办公室
- 别名：信息办（全项目通用简称）、信息化建设办（非规范简称）、信息化部（非规范叫法）
- 定义：西南大学主管信息化建设的职能部门，承担系统运营、需求审核、专家组织、验收监管等全流程管理职责。在角色侧由"信息办管理员"和"信息办领导"承接具体操作。
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 数智化建设领导小组
- 规范名：数智化建设领导小组
- 别名：领导小组（口头简称）、`leadership-group`（代码中角色 ID 复用）
- 定义：学校数智化建设的最高决策机构，负责重大项目（>200万）审定和全局战略决策。角色侧由"领导小组成员"（决策）和"领导小组办公室"（执行）承接。
- 首次出现：raw/docs/西南大学信息化项目全生命周期管理系统 — 产品详细设计方案.md

### 承建方
- 规范名：承建方
- 别名：供应商（口头简称）、服务商（服务类项目场景）、供应方（非规范叫法）
- 定义：通过招采流程中标后，负责系统建设或服务交付的外部企业。合同签订后成为项目实施的主体责任方，验收后通常转为运维团队成员。
- 首次出现：raw/docs/详细业务流程说明书-03-项目招采.md

### 工作小组
- 规范名：工作小组
- 定义：项目实施阶段组建的跨部门协作小组，由项目负责人、承建方代表、信办管理员、用户代表、技术顾问等 5 类成员构成，负责推进里程碑节点和日常协调。
- 首次出现：raw/docs/详细业务流程说明书-04-项目实施.md

### 运维团队
- 规范名：运维团队
- 定义：项目验收移交后负责日常运维的责任团队，由承建方和用户单位共同构成，执行故障工单（P0–P3）响应、定期巡检与备份恢复工作。
- 首次出现：raw/docs/详细业务流程说明书-06-项目运维.md

## 模块术语

### 需求征集模块
- 规范名：需求征集模块
- 定义：项目全生命周期第一步。信办管理员发布征集批次→二级单位填报排序审批→信办筛选审核的完整过程。V1.1 起专家评审独立为支撑流程。
- 首次出现：raw/docs/业务流程概要说明书.md

### 立项论证模块
- 规范名：立项论证模块
- 定义：需求通过筛选后，项目负责人填报申报书、组织专家论证、获得立项批复的过程。
- 首次出现：raw/docs/业务流程概要说明书.md

### 项目招采模块
- 规范名：项目招采模块
- 别名："采购管理模块"（代码菜单简称）
- 定义：立项后启动招标采购、合同签订的过程。
- 首次出现：raw/docs/业务流程概要说明书.md

### 项目实施模块
- 规范名：项目实施模块
- 定义：合同生效后，项目负责人管理项目进度、提交进展报告、处理延期/变更/终止的过程。
- 首次出现：raw/docs/业务流程概要说明书.md

### 项目验收模块
- 规范名：项目验收模块
- 定义：项目完成后，经等保测评前置→内部初验→试运行（≥1月）→正式验收→项目移交的评审过程。
- 首次出现：raw/docs/业务流程概要说明书.md

### 项目运维模块
- 规范名：项目运维模块
- 定义：项目验收后进入运维期，管理运维团队、处理故障工单（P0–P3）、执行巡检备份的过程。
- 首次出现：raw/docs/业务流程概要说明书.md

### 专家评审
- 规范名：专家评审
- 别名："专家评审流程"（全称）
- 定义：V1.1 起独立于主流程的支撑流程，可服务需求征集/立项论证/项目验收三个阶段，评审结果仅作参考，取消冷却期。
- 首次出现：raw/docs/独立流程说明书-专家评审.md

## 状态术语

### 项目阶段状态

| 规范名 | 代码值 | 定义 |
|-------|-------|------|
| 需求征集 | `demand` | 项目处于需求征集和初筛阶段 |
| 立项论证 | `reviewing` | 项目处于申报书填报、专家论证阶段 |
| 采购中 | `procurement` | 项目处于招标采购、合同签订阶段 |
| 实施中 | `implementing` | 项目处于合同执行、进度管理阶段 |
| 验收中 | `acceptance` | 项目处于初验、试运行、正式验收阶段 |
| 运维中 | `ops` | 项目已验收，处于运维期 |
| 已完成 | `completed` | 项目已移交归档 |
| 冻结 | `frozen` | 项目因特殊原因暂停，不在正常流程中 |
| 已终止 | `terminated` | 项目正式终止 |

- 首次出现：raw/docs/业务流程概要说明书.md

### 需求状态

| 规范名 | 代码值 | 定义 |
|-------|-------|------|
| 草稿 | `draft` | 项目负责人已创建但未提交需求申请表 |
| 已提交 | `submitted` | 项目负责人已填报，待单位管理员排序提交 |
| 已排序 | `sorted` | 单位管理员已排序，待分管领导审批 |
| 单位待审批 | `unit-pending` | 已提交单位领导审批，待批复 |
| 单位已批准 | `unit-approved` | 单位领导审批通过，已推送至信息办 |
| 单位已驳回 | `unit-rejected` | 单位领导驳回，退回填报人修改 |
| 信办筛选中 | `in-selection` | 信息办管理员正在结合专家评审结果筛选 |
| 已支持 | `supported` | 信息办审核通过，进入立项论证 |
| 不支持 | `not-supported` | 信息办审核未通过，本轮不予立项 |

- 首次出现：raw/docs/详细业务流程说明书-01-需求征集.md
