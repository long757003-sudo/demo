## 2. 数据迁移方案

### 2.1 专家数据结构转换
当前数据（10个字段）→ 计划数据（7个字段）

**转换规则**：
```javascript
// 当前结构 → 计划结构 映射
{
  id: e.id,                    // 保持不变
  name: e.name,                // 保持不变
  title: e.title,              // 保持不变
  dept: e.org,                 // org → dept
  category: (() => {           // type → category (中文标签)
    switch(e.type) {
      case 'tech': return '技术';
      case 'business': return '业务';
      case 'user': return '用户';
      default: return e.type;
    }
  })(),
  isExternal: e.scope === 'external',  // scope → isExternal (布尔值)
  phone: e.phone,              // 保持不变
  status: (() => {             // status → 中文标签
    switch(e.status) {
      case 'active': return '正常';
      case 'blacklisted': return '黑名单';
      default: return e.status;
    }
  })()
}
```

**字段处理说明**：
- **保留字段**：`id`, `name`, `title`, `phone` 保持不变
- **重命名字段**：`org` → `dept`, `type` → `category`, `scope` → `isExternal`
- **状态转换**：`active` → `正常`, `blacklisted` → `黑名单`
- **丢弃字段**：`field`（研究领域）, `email`（邮箱）计划数据结构中不存在，将被丢弃
- **黑名单信息**：`blackReason`和`blackDate`将提取到单独的`blacklist`数组中

**黑名单数据迁移**：
- 当前：专家状态为`blacklisted`，有`blackReason`和`blackDate`字段
- 计划：专家状态为`黑名单`，黑名单原因和时间存储在其他地方（计划中的`blacklist`数组）
- 方案：将`blackReason`和`blackDate`提取到单独的`blacklist`数组中

## 4. 评审管理视图实现

### 4.1 `review-list`视图（更新现有实现）
**计划要求**：
- 显示所有评审记录（论证+验收）
- 使用`renderTable`函数统一表格样式
- 包含类型标签、状态标签、操作列

**更新要点**：
- 调整列顺序为：评审名称、类型、项目、发起日期、评审日期、状态、结论、操作
- 使用计划指定的状态标签样式
- 操作列：进行中→详情链接，已完成→报告下载链接

### 4.2 `review-launch`视图（新增）
**计划要求**：
- 发起论证评审表单
- 专家选择表格，含BR-05实时验证
- 表单字段：关联项目、评审类型、计划评审日期、评审地点

**实现要点**：
- 专家选择表格：显示所有非黑名单专家，预选5名专家（含2名校外）
- BR-05验证：实时计算校外专家比例，显示验证结果
- 提交验证：比例不足1/3时阻止提交并显示toast提示
- 成功提交：调用`logOperation`，显示成功toast，跳转回列表

### 4.3 `review-opinion`视图（新增）
**计划要求**：
- 专家填写评审意见表单
- 五个维度评分（必要性、可行性、安全性、经济性、进度合理性）
- 主要意见、修改建议、论证结论三个部分

**实现要点**：
- 评分组件：1-5分单选按钮
- 文本区域：主要意见和修改建议
- 结论选择：通过/修改后通过/不通过
- 提交验证：主要意见必填

### 4.4 `my-reviews`视图（新增）
**计划要求**：
- 专家角色的待处理评审任务列表
- 每个任务卡片显示项目名称、评审类型、评审日期
- 操作按钮：填写评审意见

**实现要点**：
- 过滤`DATA.reviews`中状态为`进行中`的记录
- 卡片式布局，每项任务一个卡片
- 从`my-reviews`可跳转到`review-opinion`并传递评审ID

## 8. 风险与缓解

### 8.1 数据迁移风险
**风险**：数据转换错误导致字段丢失或值错误
**缓解**：
- 创建数据备份（注释掉原有数据）
- 编写验证脚本检查转换结果
- 分步骤迁移，先测试少量数据

### 8.2 功能依赖风险
**风险**：其他模块依赖`experts`数据结构的代码可能中断
**缓解**：
- 检查`review-launch`等依赖专家数据的视图
- 更新所有使用`experts`的代码使用新字段名
- 全面测试评审发起流程

### 8.3 导航中断风险
**风险**：ID变更导致现有书签或直接链接失效
**缓解**：
- 更新所有`navigate`调用使用新ID
- 测试从其他模块跳转到专家管理的链接
