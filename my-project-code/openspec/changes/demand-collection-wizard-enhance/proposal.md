# Proposal：优化【需求征集】列表字段与创建向导流程

## 为什么做

当前「需求征集」模块存在以下问题：

1. **列表字段信息不足**：`demand-collect` 列表页仅展示「征集标题、年度、征集周期、状态、需求数、操作」，缺少「摘要、通知联系人、联系方式、征集范围」，管理员在列表页无法快速了解每个征集方案的核心信息，必须点进详情才能确认。

2. **创建向导步骤语义不清**：当前 4 步向导（征集说明配置 → 通知设置 → 业务流程配置 → 总览确认）中，Step 0「征集说明配置」缺少「摘要」和「联系方式」两个字段，这两个字段本应是征集基础信息的一部分。

3. **通知设置体验割裂**：Step 1「通知设置」是一个轻量表单，但用户在创建通知时也希望能从现有模板导入内容，目前需要先去通知模板库查找，再手工录入，步骤割裂。`notification-create` 视图已有「从模板导入」能力，但创建向导中未复用。

4. **流程配置缺少专家评审控制**：Step 2「业务流程配置」中，节点之间的「专家评审」属于独立的可配置维度，当前每个节点下方有「+ 插入评审节点」按钮（Mock），但交互未明确体现为"在两节点之间选择是否需要专家评审"的语义，不够直观。

---

## 需求边界

### 做什么

**1. 需求征集列表新增字段**

在 `demand-collect` 列表表格中新增以下列（插入到「状态」列之后）：

| 新增列 | 字段来源 | 展示方式 |
|--------|---------|---------|
| 摘要 | `plan.summary` | 文本，超过 40 字截断加省略号 |
| 通知联系人 | `plan.contactName` | 纯文本 |
| 联系方式 | `plan.contactInfo` | 纯文本（电话或邮箱） |
| 征集范围 | `plan.scopeDesc` | 文本，描述部门/角色/指定人范围 |

同步在 `data.js` 的 `collectionPlans` 中为现有 Mock 数据补充上述字段。

**2. 创建向导改为三步流程**

原 4 步（Step 0-3）重组为 3 步 + 1 个总览确认页：

| 步骤 | 标题 | 内容说明 |
|------|------|---------|
| Step 1 | 征集基础信息 | 现有 Step 0 全部字段 + 新增「摘要（必填）」字段（通知联系人/联系方式等通知相关字段全部归到 Step 2） |
| Step 2 | 通知信息 | 嵌入 `notification-create` 的通知表单布局，顶部「从模板导入」Card 默认展开且模块预选「需求征集」；包含通知标题、正文、联系人、联系方式、接收范围、发送渠道、发送时间等全部通知字段 |
| Step 3 | 流程配置 | 现有 Step 2 节点图，两节点之间改为「是否需要专家评审」开关（替代「+ 插入评审节点」按钮），默认不勾选 |
| 总览确认 | — | 现有 Step 3，三步信息汇总 + 提交审批按钮 |

**2a. Step 1 — 征集基础信息新增字段**

在「征集说明」`textarea` 之后、「开始日期」之前，插入：
```
摘要（必填）：单行文本输入，id="cc-summary"，placeholder="请输入一句话摘要（100字以内）"
```
注意：Step 1 只保留征集基础信息，所有通知相关字段（联系人、联系方式、接收范围等）全部放到 Step 2 通知编辑页面。

**2b. Step 2 — 通知信息页**

- 顶部渲染「从模板导入」Card（与 `notification-create` 的 Card A 结构完全相同）
- 默认展开（不折叠），「模块」下拉默认选中「需求征集」，列表自动过滤并显示需求征集相关模板
- 下方渲染通知表单字段：通知标题、通知正文、联系人、联系方式、接收范围、发送渠道、发送时间
- 「导入」按钮回填「通知标题」和「通知正文」字段，行为与 `notification-create` 完全一致
- 模板数据内联到当前视图脚本段（`_importTmplData`，与 `notification-create` 中结构相同，独立复制）

**2c. Step 3 — 流程配置专家评审开关**

两个主节点之间（节点图中间隙处）渲染评审开关，替代原「+ 插入评审节点」按钮：
```
[节点A] — [专家评审开关] — [节点B]
```
- 开关控件：`<label><input type="checkbox"> 需要专家评审</label>`（默认不勾选）
- 取消勾选时，节点间连线样式变为虚线（视觉反馈，CSS class 切换）
- 开关状态存入 `window._collectWizard.data.reviewConfig`（数组，长度 = 节点数-1）

### 不做什么

- 不修改 `collection-detail` 详情页
- 不修改 `notification-create` 视图本身（只是在向导中复用相同 UI 布局，独立渲染）
- 不实现模板数据的跨视图引用（各视图内联自己的模板数据副本）
- 联系方式字段不做格式校验（Demo 阶段）
- 不新增持久化接口，字段更新仅为 Mock 静态数据
