## Spacing Scale

基准：8pt 网格（multiples of 4）。所有间距必须使用以下 token 或 Tailwind 对应类。

| Token | Value | Tailwind | Usage |
|-------|-------|----------|-------|
| xs | 4px | `p-1` / `gap-1` | 图标与文字间距、内联 padding |
| sm | 8px | `p-2` / `gap-2` | 紧凑元素间距、badge 内边距 |
| md | 16px | `p-4` / `gap-4` | 默认元素间距、表单字段间距 |
| lg | 24px | `p-6` / `gap-6` | 卡片内边距、内容区 padding |
| xl | 32px | `p-8` / `gap-8` | 分组间距、表单区块间距 |
| 2xl | 48px | `py-12` | 主要区块分隔 |
| 3xl | 64px | `py-16` | 页面级间距（慎用） |

**例外**：
- 侧边栏宽度固定 220px（`var(--sidebar-width)`，来自 demo-0408）
- 顶部导航高度固定 56px（`var(--header-height)`）
- 内容区左右 padding 固定 24px（`padding: 20px 24px`，来自 `layout-content`）
- 拖拽排序项垂直间距 8px，触控目标最小高度 44px

## Color

> Source: demo-0408/shared/style.css CSS 变量。ui-spec.md Tailwind config 为补充约束。

### 主色板（CSS 变量，须在 `<style>` 内声明 `:root { ... }`）

| Role | CSS Variable | 近似 Hex | Tailwind 扩展 | Usage |
|------|-------------|---------|--------------|-------|
| Dominant (60%) | `var(--bg-layout)` | `#f8fafc` | `bg-background` | 页面背景、主内容区底色 |

**Accent 保留用途（仅限以下元素）**：
1. 侧边栏当前激活菜单项文字色（`var(--sidebar-active-text)` #5eead4）
2. 链接默认色（`var(--accent)` #0f766e）
3. 进度条已完成节点高亮色
4. 遴选页"支持"操作按钮（仅支持/不支持二元选择中的肯定按钮）
5. 生命周期进度条中"当前阶段"节点色

**语义色**：

| 语义 | CSS Variable | Hex | 用途 |
|------|-------------|-----|------|
| Success | `var(--success)` | `#15803d` | 审批通过、已采纳 Badge、已读状态 |
| Warning | `var(--warning)` | `#a16207` | 待审批 Badge、临近截止（7天内橙）、退回状态 |
| Danger | `var(--danger)` | `#dc2626` | 已拒绝、超期、不支持标记、BR-04 提示 |
| Info | `var(--info)` | `#1d4ed8` | 征集中 Badge、一般信息通知 |

**Badge（状态标签）色彩规则**（class `tag tag-{color}`，来自 demo-0408）：

| 状态 | Badge 类 | 含义 |
|------|---------|------|
| 草稿 | `tag tag-gray` | 灰色 |
| 待审批 / 已退回 | `tag tag-orange` | 橙色 |
| 征集中 / 已采纳 / 已通过 | `tag tag-green` | 绿色 |
| 遴选完成 / 已送达未读 | `tag tag-blue` | 蓝色 |

#### 视图 D：项目负责人需求申请表（视图 #5，T3 四步向导）

**文件路径**：`pages/demand-fill.html`
**可访问角色**：`project-manager`、`project-assistant`
**模板**：T3 — 四步向导（`renderStepWizard`）

**向导步骤**：

| Step | 标题 | 字段 |
|------|------|------|
| 0 | 基本信息 | 项目名称（必填）、所在单位（只读，自动填入）、负责人姓名（只读）、联系方式（必填）、预期投入金额（必填，输入后自动触发项目类型判断并展示类型 Badge） |
| 1 | 需求描述 | 摘要（必填，≤200字，字符计数器）、功能描述（textarea，必填）、优先级（radio：高/中/低） |
| 2 | 技术要求 | 技术方案描述（textarea）、标签选择（checkbox 从预设标签库多选，如：数据分析/移动端/集成接口/报表）、与现有系统的关系（select：全新建设/功能扩展/系统替换） |
| 3 | 附件上传 | 文件上传（PDF/Word/Excel，多文件，仅演示）、备注说明（textarea，选填） |

**草稿机制**：
- 每次字段变更自动 `saveDraft('demand-fill', data)`（localStorage）
- 页面加载时 `loadDraft('demand-fill')` 恢复
- 步骤切换时不丢失已填内容（state 保存在 `window._demandFormData`）

**底部操作区（DEM-03）**：
- 「暂存草稿」（secondary）→ `showToast('草稿已保存')`
- 「上一步」（secondary，Step 1-3 显示）
- 「下一步」（primary，Step 0-2）/ 「提交审核」（primary，Step 3）→ 提交后 `navigate('demand-list')`，`showToast('需求已提交，等待单位系统管理员处理')`

### 变更 4：`demand-selection`

#### 视图 G：信息办需求遴选页（视图 #7，T4）

**文件路径**：`pages/demand-select.html`
**可访问角色**：`info-admin`（遴选操作）、`info-leader`（确认）
**模板**：T4 — 详情模板

**页面结构**：

| 区域 | 内容 |
|------|------|
| 页面头部 | "需求遴选 — [批次名称]" + 当前阶段 Badge + 汇总统计（总需求数 / 已支持 / 不支持 / 未处理） |
| 筛选栏 | 按单位 select + 按状态 select（全部/已支持/不支持/未处理）+ 搜索框 |
| 遴选列表（主区域） | 逐条需求展示，每条一个卡片行（见下） |
| 操作记录 Tab | 所有 T4 必须包含此 Tab |

**遴选卡片行结构（每条需求）**：
```
[序号] [项目名称]  [单位]  [负责人]  [预算 + 类型Badge]  [当前状态Badge]
      描述摘要（一行，最多 60字截断）
      [支持] [不支持] 按钮 — 右对齐
```

**支持/不支持交互（DEM-06，BR-04）**：

- 点击「支持」：
  - 按钮变为 accent 绿色填充，状态 Badge 更新为"已支持"（`tag tag-green`）
  - `showToast('已标记为支持')`
  - 支持按钮无需二次确认

- 点击「不支持」：
  - 弹出 Modal（标题："不予支持原因"）
  - Modal 内容：BR-04 六类原因单选列表（radio group）：

  | 序号 | BR-04 六类不予支持原因 |
  |------|----------------------|
  | 1 | 与现有系统功能重复，无差异化说明 |
  | 2 | 已建/在建项目重复申报 |
  | 3 | 需求描述不明确或预算明显背离实际 |
  | 4 | 技术路线过时，不符合学校技术发展方向 |
  | 5 | 已被否决且无新理由或新情况说明 |
  | 6 | 不符合学校其他相关规定 |

  - 还需填写"补充说明"textarea（选填）
  - Modal 底部：「确认不支持」（destructive）/ 「取消」
  - 确认后：状态更新为"不支持"（`tag tag-red`），`showToast('已标记为不支持')`
  - 可撤销：再次点击"不支持"的已选项，弹 confirm modal "确认撤销不支持标记？" → 撤销后恢复为"未处理"

**info-leader 操作**：
- 遴选完成后显示「确认遴选结果」按钮（primary）→ confirm modal "确认后需求将进入需求库，无法撤回。" → `showToast('遴选结果已确认，需求已入库')`

## Interaction Contracts

### 角色切换机制（复用 demo-0408 core.js）
- 顶部导航右侧 `<select class="role-select">` 切换角色
- `switchRole(roleId)` 存入 localStorage，重新渲染导航和内容
- Phase 1 涉及角色：`info-admin`、`unit-sysadmin`、`project-manager`、`unit-leader`、`info-leader`

### 拖拽排序（DEM-04，视图 E）
- 使用 HTML5 原生 Drag and Drop API
- `draggable="true"` 属性加在每个需求行 `<tr>` 或 `<div>` 上
- 事件：`dragstart` → 记录源行 index；`dragover` → 阻止默认行为 + 显示插入指示线（2px solid `var(--accent)`）；`drop` → 重排 DOM + 更新序号
- 拖拽手柄使用 Lucide `grip-vertical` 图标（w-4 h-4，颜色 `var(--text-muted)`）
- 排序完成后序号自动重新编号（1、2、3...）

### 生命周期进度条（T4 页面，视图 F）
- 横向进度条，等分 6 个节点：需求征集 / 立项论证 / 采购 / 实施 / 验收 / 运维
- 当前阶段：蓝色填充圆点 + 加粗标签（`var(--accent)` 或 `var(--info)`）
- 已完成阶段：绿色填充圆点（`var(--success)`）+ 连接线绿色
- 未开始阶段：灰色空心圆点（`var(--text-muted)`）+ 连接线灰色
- Phase 1 中：需求征集节点 = 当前阶段

### 四步向导（视图 D）
- 使用 `renderStepWizard(steps, currentStep)` 渲染步骤指示器
- 步骤切换时页面不刷新（纯 JS DOM 替换内容区）
- 状态保存在 `window._demandFormData` 对象（同 demo-0408 proposal-fill 模式）

### BR-04 不支持原因 Modal
- 必须选择一个原因才可点击「确认不支持」（未选时按钮 disabled 并提示"请选择不支持原因"）
- radio group 展示 6 条原因，样式：`<label class="flex items-center gap-2 ...">` + radio + 文字
- Modal 最小宽度 480px，最大高度 80vh（超出可滚动）

### Toast 规范
- 使用 `toast(msg, type, duration)` — type: `success` / `error` / `warning` / `info`
- 成功操作：type `success`，duration 2000ms
- 错误提示：type `error`，duration 3000ms
- 所有操作均需 toast 反馈，禁止无响应操作
