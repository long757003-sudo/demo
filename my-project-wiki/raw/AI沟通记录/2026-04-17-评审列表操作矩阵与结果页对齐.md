## 背景与问题

- 评审列表「查看评审结果」按钮原路由到 `registerView('review-launch')`，但该视图无论是否带 `id` 都渲染 4 步创建向导，导致专家/管理员点开看到空表单，语义割裂。
- `actionCell` 非专家分支包含 `填写意见 → review-opinion` 链接，所有非专家角色（info-admin / info-leader / leadership-office / PM）都能点到；这是专家专属动作，违反 CLAUDE.md"角色操作列禁止 else 兜底"规则。
- 「详情」通用入口在 in-progress / invitation-pending / not-started / rework-pending 状态下没有对应只读视图。

## 关键结论

### 1. review-launch 只读分支（已完成评审专用）
- 在 `review-launch` 入口新增早返回：当 `existing.status ∈ {passed, rejected, timeout-rejected}` 时走 `renderReviewResult(r)`，不进向导。
- `renderReviewResult` 4 块内容对齐 `requirement-review.html` STEP 04：基本信息 / 综合评分 / 评分明细（5 维度）/ 评审结论 / 综合意见。
- 数据侧为 RV002/RV003/RV004 新增 `scoreBreakdown` 字段（5 维度 · 加权结果≈原 `weightedScore`：52/86/78）。

### 2. 非专家操作列按角色×状态重写

| 状态 | info-admin | info-leader | leadership-office |
|---|---|---|---|
| 邀请中 | 催办 (toast) | — | — |
| 未开始 | 提醒准时 (toast) | — | — |
| 进行中 | 进入工作台 (role=owner) | 进入工作台 | — |
| 退回修改中 | 查看退回 + 通知 PM | 查看退回 | — |
| 已通过 | 查看评审结果 | 查看评审结果 | 查看评审结果 |
| 不通过 / 超时未修改 | 查看评审结果 + 发起重评 | 查看评审结果 | 查看评审结果 |

- 删除"填写意见"泄漏、删除对未完成状态的假"详情"。
- 用 `isAdmin / isLeader / isOffice` 显式分发，最终 `return dash` 仅兜未知状态。

## 可复用的方法/模板

### 角色操作列显式分发模板
```js
if (r.status === 'X') {
  if (isAdmin)  return adminAction;
  if (isLeader) return leaderAction;
  if (isOffice) return dash;
}
// 最终兜底仅对未知状态
return dash;
```
CLAUDE.md 规则："else 只允许作为'确实只读/无操作'的兜底；该有按钮却落入 else 视为遗漏"。

### 只读视图与向导共用 registerView 的分支模式
```js
registerView('X', function() {
  var existing = rid && DATA.find(r => r.id === rid);
  if (existing && ['完成态'].includes(existing.status)) {
    return renderResultView(existing);   // 只读
  }
  // 原创建向导逻辑
});
```
避免为只读视图单开 `view-id`，保持路由表稳定。

### 自检报告三段式（CLAUDE.md 强制）
```
【改动】<一句话>
【自检结果】
  ✅ 断言 — 实测
  ⚠️ 已知风险 / 未覆盖项
【需人工验证】
  - <需用户点击确认的路径>
```

### 跨文件字段扩展的加权分数对照法
新增 `scoreBreakdown` 时按 `value·weight/100` 回算应≈既有 `weightedScore`，保证 demo 数据自洽（RV002 52.5≈52 / RV003 86.15≈86 / RV004 78.25≈78）。
